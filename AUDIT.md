> Generated from a 78-agent audit workflow (find → adversarially verify → synthesize).

## Decisions locked in (2026-06-24)

- **Scope:** implement **all 17** fixes.
- **Network access:** **localhost only** — bind `127.0.0.1` by default, opt-in expose via `BIND_HOST`. **No auth token.**
- **Restart behavior:** **preserve & adopt** — restart re-adopts running topology via `reconcile()`; clean shutdown does not wipe; explicit wipe via `start.sh --clean` / `stop.sh --teardown`.

## Executive summary

The audit's 66 findings collapse into one dominant systemic defect with a handful of supporting ones. The dominant defect: the DockerManager treats its volatile in-memory dicts (self.nodes, self.links, SubnetPool._next_id) as the source of truth, while the actual source of truth is the Docker daemon, which outlives the manager process. There is no startup reconciliation bridging the two. After any crash (where neither stop.sh nor the lifespan shutdown ran), live labeled containers/networks survive but the fresh process is blind to them, producing the confirmed 409 network-name collision, subnet-pool re-issue collisions, silent force-removal of orphan containers, and accumulating leaks. Compounding this, every multi-step provisioning path (create_link, create_node, import) is non-transactional and non-idempotent, so any partial failure orphans real Docker resources with no in-memory record. A second, independent class is security: an unauthenticated control plane bound to 0.0.0.0 drives privileged containers, with shell-injection sinks (send_bundle) and filesystem path-traversal sinks (scenario export/import/delete) reachable anonymously — effectively remote host root. A third class is concurrency: blocking docker subprocess calls run directly on the asyncio event loop and on an unbounded threadpool with zero locking around shared mutable state. The fix plan is anchored by three prevention-defining changes — (1) a mandatory startup reconcile() making Docker the single source of truth, (2) idempotent get-or-create + transactional rollback for all resource provisioning, and (3) a single hardened argv-based exec primitive plus localhost-default bind with auth — backed by a shared label-based preflight prune in start.sh and event-loop offloading. Verified against source: docker_manager.py confirms empty __init__ (37-43), unconditional networks.create (176-181), counter-only SubnetPool reset to 0, Node(0,'') sentinel (250-253), unguarded cleanup_all container loop (462-465); main.py confirms unconditional lifespan cleanup_all (28); start.sh confirms --host 0.0.0.0 (99) and no orphan prune.

## Root-cause analysis

Three systemic causes explain the 66 symptoms. CAUSE A — Volatile state treated as source of truth, no reconciliation (the largest cluster: ~16 findings across state-reconciliation, scenario-io, ion-models). The manager initializes empty dicts and a counter-based SubnetPool on every start and never queries Docker for ionmgr.managed resources. Every downstream symptom — the 409 on create_link, subnet re-issue, _next_node_id colliding with and silently clobbering orphan containers, cleanup_all only seeing labeled resources, import's cleanup-then-recreate starting from an unknown baseline, generated start.sh pruning by subnet-substring instead of name — is a consequence of in-memory and Docker state being allowed to diverge with no convergence step. CAUSE B — Non-transactional, non-idempotent, fail-silent provisioning (cluster: create_link rollback, create_node leftovers, _docker_exec swallowing non-zero exits, _wait_for_ion_ready advisory-not-gating, fixed sleeps, entrypoint ignoring ionstart failure, no HEALTHCHECK). Resources are created in multiple steps, tracked in-memory only on the success path (self.links set last at line 219), and errors are swallowed (_docker_exec just passes on non-zero, line 917-918), so partial failures leak Docker objects AND record state as healthy when it is not. CAUSE C — Unauthenticated privileged control plane with unsafe string-interpolation and unconfined filesystem joins, plus blocking I/O on the event loop with no locking. The same root (input/commands assembled as shell strings and paths joined to a base dir without confinement; sync docker calls invoked from async coroutines; shared dicts mutated by concurrent threadpool requests) produces command injection (send_bundle), four path-traversal endpoints, event-loop stalls, and dict-changed-during-iteration races. The frontend findings are downstream of CAUSE A/B (UI shows stale/fabricated state because the backend desyncs and errors are swallowed at the fetch layer). De-duplication note: the create_link partial-failure/rollback finding appears three times (state-reconciliation, api-async, ion-models/timeout) and is merged; the 0.0.0.0 bind appears twice (scripts-deploy, security) and is merged; the path-traversal endpoints appear in both scenario-io and security and are merged into one confinement-helper fix; the Dockerfile unpinned-clone appears twice (scripts-deploy, security) and is merged.

## Prioritized fixes

### #1 — Add mandatory startup reconcile()/adopt() — make the Docker daemon the single source of truth
**Severity:** critical · **Effort:** large  
**Files:** `backend/services/docker_manager.py`, `backend/services/subnet_pool.py`, `backend/main.py`

- **Problem:** DockerManager.__init__ (lines 37-43) initializes empty self.nodes/self.links and a fresh SubnetPool(_next_id=0) and never queries Docker for ionmgr.managed resources. After a crash, live containers ionmgr_n* and networks ionmgr_link_* survive but the new process is blind to them, causing the confirmed create_link 409 (line 176), subnet re-issue collisions, and silent clobbering of orphan containers by _next_node_id (877-881). This is the architectural root of the whole orphaned-state/restart-desync class.
- **Fix:** Add a reconcile() method, call it at the end of __init__ and expose it for re-run. (1) List containers via self.client.containers.list(all=True, filters={'label': LABEL_KEY}) (reuse the cleanup_all pattern at 462). Parse node_id from name 'ionmgr_n{id}' or a new ionmgr.node_id label; rebuild self.nodes with real container_id/container_name and status derived from container.status (RUNNING vs ERROR for exited/created). (2) List networks via networks.list(filters={'label': LABEL_KEY}); for each, call network.reload(), parse {a}_{b} from name, read actual subnet from network.attrs['IPAM']['Config'][0]['Subnet'], read each container's assigned IPv4 from network.attrs['Containers'], and rebuild self.links + node.ip_addresses from that live data. Mark half-built links (only one container connected / no ION config) status=ERROR. (3) Seed _next_node_id from max(parsed container ids)+1 and add SubnetPool.reserve(idx)/from_live(indices): for every adopted network parse the 3rd octet (only when 2nd octet == self.base) and reserve it, setting _next_id past the max. Add explicit ionmgr.node_id / ionmgr.link_id labels at create time so parsing is robust to name drift. Add an idempotency invariant test: construct the manager twice over the same live topology and assert nodes/links/subnets match the daemon.
- **Prevention:** Startup reconciliation that adopts every labeled resource makes restart idempotent and eliminates empty-dict-after-restart as a possible state. All id/subnet counters are seeded from live state, so allocation can never collide with crash survivors.
- **Risk:** Mis-parsing a network name or foreign 172.50.x network could mis-adopt; mitigate by filtering on the label AND 2nd-octet match, and by marking ambiguous resources ERROR rather than deleting. network.attrs is cached — call reload() first. Test with the two-construct invariant test plus a fixture topology.

### #2 — Make all Docker resource creation idempotent (get-or-create) and transactional (rollback on partial failure)
**Severity:** high · **Effort:** large · depends on [1]  
**Files:** `backend/services/docker_manager.py`

- **Problem:** create_link calls networks.create() unconditionally (176-181): a leaked/concurrent same-named network yields 409 and permanently breaks link creation (the confirmed incident). The body (176-219) has no try/except: any failure after the network exists leaks the network + subnet because self.links is set last (219). _docker_exec swallows non-zero exits (917-918) so a half-configured ION link is recorded as UP. create_node leaves /tmp config dirs and does not check bpsink launch. _docker_exec has timeout=10 with no TimeoutExpired handler, raising mid-create.
- **Fix:** Add _get_or_create_network(name, subnet): try networks.get(name); if found, reload(), read its real subnet from attrs['IPAM']['Config'][0]['Subnet'], reuse it and release/reconcile the just-allocated SubnetPool index (parse 3rd octet, call subnet_pool.release(idx) — mirror delete_link 264-268), and re-derive ip_a/ip_b from the real subnet's 3rd octet; catch APIError 409 from create() as a race and fall back to get(). Wrap the whole create_link body in try/except with local flags (network_created, connected_a, connected_b): on any exception, best-effort disconnect both containers (force=True), network.remove() if created here, subnet_pool.release(subnet_idx), then re-raise. Make _docker_exec catch subprocess.TimeoutExpired (return a sentinel / raise a typed IonExecError) and, for the four ION config calls in create_link (194-202), surface non-zero/timeout — but treat 'duplicate/already exists' stderr as success (see repair_ion_config 815). On unrecoverable ION-config failure, record the link with status=ERROR and let repair_ion_config/reconcile re-apply rather than leaving it UP. In create_node, replace the fixed sleep(2) (99) with _wait_for_ion_ready before launching bpsink, verify bpsink actually started (pgrep/log check, since it is backgrounded), set status=ERROR on failure, and sweep leftover /tmp/ion_n{id}_* dirs. Apply the same get-or-create network removal in cleanup_all by name pattern (ionmgr_link_*) as a belt-and-suspenders for unlabeled same-named networks.
- **Prevention:** Every resource-creating path becomes create-then-rollback and idempotent-by-deterministic-name, so partial failures and pre-existing resources can never leak or 409. State recorded matches what the system actually achieved (status=ERROR when ION config did not verify).
- **Risk:** Naively raising on any non-zero ION admin exit can convert benign 'duplicate' warnings into false rollbacks — must classify stderr. Remove-then-create on an existing network could destroy a foreign network; prefer adopt-if-labeled-and-healthy, remove only stale/unlabeled. Test by injecting connect/exec failures mid-create_link and asserting no orphan network/subnet remains.

### #3 — Harden container command execution: single argv-based exec primitive, eliminate bash -c interpolation (command injection)
**Severity:** critical · **Effort:** medium  
**Files:** `backend/services/docker_manager.py`

- **Problem:** send_bundle (335-338) interpolates a fully user-controlled message into bash -c inside a --privileged container; the f-string double-quote is trivially broken out of, giving anonymous remote root on the host. _ion_exec (903-908) wraps commands in single quotes via echo '{cmd}' | tool with no escaping. These sinks are reachable from unauthenticated HTTP endpoints.
- **Fix:** Introduce one exec primitive that takes an argv list (never a shell string) plus optional stdin: subprocess.run(['docker','exec','-i',container,tool], input=command+'\n', ...). Rewrite _ion_exec to feed the admin command via stdin to bpadmin/ipnadmin instead of echo|bash -c. Rewrite send_bundle as subprocess.run(['docker','exec',container,'bpsource', f'ipn:{int(to_node)}.1', message]) so message is argv, never shell-parsed. Migrate other interpolating callsites (_get_interface line ~925, tc/tail commands) to the same primitive. Where a shell is genuinely unavoidable, shlex.quote every interpolated value. Add a CI grep that fails on 'bash", "-c' combined with f-string interpolation in this module.
- **Prevention:** A single argv-based exec chokepoint structurally removes shell parsing of any interpolated value, so injection cannot be reintroduced per-callsite; the CI grep enforces it.
- **Risk:** docker exec -i with stdin must keep the admin tool reading until EOF; verify bpadmin/ipnadmin accept piped stdin (they already do via the current echo pipe). Low behavioral risk. Test send_bundle with a message containing quotes/$()/backticks and assert no execution.

### #4 — Default-bind to 127.0.0.1, add an auth token, and cap resource creation
**Severity:** critical · **Effort:** medium  
**Files:** `start.sh`, `backend/main.py`, `backend/api/scenarios.py`, `backend/api/websocket.py`

- **Problem:** uvicorn launches with --host 0.0.0.0 (start.sh line 99) and the app has no authentication, authorization, or CORS restriction. Every endpoint — create privileged container, exec ION commands, send_bundle (RCE), cleanup, import (destructive), delete files — is reachable by any network peer. No rate limit / node cap makes it a resource-exhaustion vector too.
- **Fix:** Change start.sh line 99 to --host "${BIND_HOST:-127.0.0.1}" and add an explicit --expose/BIND_HOST opt-in. Add a FastAPI dependency verify_token reading IONMGR_TOKEN from env, applied to all mutating/HTTP routes via Depends; manually enforce the same token on the WebSocket endpoints (FastAPI auth deps and CORS do not cover WebSockets). Refuse to start (or refuse 0.0.0.0) when exposed without a token. Add MAX_NODES/MAX_LINKS caps enforced in create_node/create_link and at import time. Do NOT enable permissive CORS.
- **Prevention:** Localhost-by-default plus mandatory token caps blast radius; a privileged control plane can never be exposed anonymously by default, and resource caps bound exhaustion.
- **Risk:** Binding 127.0.0.1 narrows network reach but does not stop other local users — the token is the real control. Ensure existing local clients pass the token. Test that WebSocket endpoints reject missing/invalid tokens.

### #5 — Confine all scenario filesystem access through one validated path helper (path traversal: export/import/delete)
**Severity:** high · **Effort:** small  
**Files:** `backend/api/scenarios.py`

- **Problem:** export_scenario (39-103) builds filename from unsanitized meta.name and write_text — arbitrary-location file write/overwrite. delete_scenario (331-338) and import_scenario_from_disk (216-229) join a raw user filename to SCENARIOS_DIR (pathlib lets '..' and absolute operands escape) — arbitrary file delete and arbitrary JSON read. export_bundle already sanitizes (line 360), proving the inconsistency.
- **Fix:** Create _safe_scenario_path(filename): take Path(filename).name, require it to match ^[A-Za-z0-9_.\-]+\.json$, then compute (SCENARIOS_DIR / name).resolve() and assert it .is_relative_to(SCENARIOS_DIR.resolve()) (Python 3.10 confirmed available), raising HTTPException(400) otherwise. For export, sanitize meta.name via re.sub(r'[^A-Za-z0-9_\-]', '_', name) (matching export_bundle) before building the .json filename and run it through the containment assert. Route export, export_scenario write, delete_scenario.unlink, and import_scenario_from_disk.read_text through this single helper. Add a test that '../' and absolute names cannot escape SCENARIOS_DIR.
- **Prevention:** One shared sanitize+confine gate for every disk-touching endpoint makes the traversal class structurally impossible and prevents a new endpoint from being the unsanitized outlier.
- **Risk:** Low; ensure the regex still permits legitimate existing scenario names. is_relative_to is the load-bearing check (regex alone misses absolute operands).

### #6 — Add a shared label-based orphan-prune preflight to start.sh (and reconcile with stop.sh teardown)
**Severity:** high · **Effort:** small · depends on [1]  
**Files:** `start.sh`, `stop.sh`

- **Problem:** start.sh (33-103) never enumerates/removes leaked ionmgr.managed containers/networks before launching uvicorn, so crash leftovers trigger the create_link 409 and strand subnets. Cleanup is coupled only to graceful exit (stop.sh, lifespan) — both skipped on SIGKILL/OOM/reboot. The leaked-network reaping is the always-missing piece (orphan containers are partly self-healed by create_node 58-63).
- **Fix:** Factor the label-based teardown into a shared sourced function (docker/lib_cleanup.sh) used by both stop.sh and start.sh. In start.sh, before launching uvicorn AND only in the branch where no live owned PID exists (so a still-running instance is never wiped), prune containers first then networks: docker ps -aq --filter label=ionmgr.managed | xargs -r docker rm -f; docker network ls -q --filter label=ionmgr.managed | xargs -r docker network rm (ignore not-found). Guard stop.sh so that if `docker info` fails it reports cleanup could not run rather than exiting 0. This complements (does not replace) the in-app reconcile in rank 1 — the shell reaper handles the crash case where the manager has not yet started.
- **Prevention:** Orphan reaping becomes an idempotent step that runs on every start independent of how the prior process ended, so the namespace is empty before any allocation begins.
- **Risk:** Must not run while a live owned instance exists — gate on the no-live-PID branch. Network prune fails if containers still attached, so prune containers first (ordering matters). For true crash resilience document running under systemd with Restart= and ExecStartPre calling the reaper.

### #7 — Decouple resource lifecycle from process lifecycle (stop wiping topology on clean restart; reconcile on crash)
**Severity:** medium · **Effort:** medium · depends on [1]  
**Files:** `backend/main.py`, `stop.sh`

- **Problem:** The lifespan shutdown unconditionally calls cleanup_all() (main.py 28), so a routine restart destroys the user's entire topology, while a crash skips it and leaks everything — exactly backwards. stop.sh also unconditionally tears down labeled resources in both graceful and --force modes, so a normal ./stop.sh && ./start.sh cycle cannot preserve topology.
- **Fix:** Remove cleanup_all() from the lifespan shutdown by default; gate it behind IONMGR_CLEANUP_ON_EXIT=1 for dev. On startup rely on reconcile() (rank 1) to re-adopt running resources; optionally persist intended topology to a scenarios/state JSON to detect drift. Reconcile stop.sh: make its teardown an explicit operator action (default stop = leave resources, --teardown to wipe), or document that stop.sh intentionally wipes and provide a separate stop-preserve path. Ensure the lifespan change and stop.sh behavior agree so restart actually preserves.
- **Prevention:** Startup reconciles/adopts, shutdown preserves, destruction is an explicit operator action — eliminating both accidental-wipe and crash-leak failure modes.
- **Risk:** Changing stop.sh default teardown is a behavior change operators rely on; document clearly and keep an explicit teardown flag. Depends on reconcile existing or restart leaves orphans unadopted.

### #8 — Add a single-writer lock around all manager state mutations and snapshot reads
**Severity:** high · **Effort:** medium · depends on [2]  
**Files:** `backend/services/docker_manager.py`, `backend/api/websocket.py`

- **Problem:** self.nodes/self.links/_config_dirs/subnet_pool/_link_id_counter have no lock. FastAPI sync routes run in parallel threadpool threads while async websocket loops iterate the same dicts, causing: TOCTOU id/subnet allocation races (two POST /api/nodes computing the same _next_node_id 877-881), 'dictionary changed size during iteration' in get_topology while delete_node mutates self.links, and cleanup_all vs create_link inconsistency.
- **Fix:** Add a threading.RLock (RLock because delete_node calls delete_link and cleanup_all calls both — reentrancy required). Guard every public mutating method (create_node, create_link, delete_node, delete_link, cleanup_all, import-driven creates). Keep the slow docker/subprocess work OUTSIDE the lock; hold the lock only around the dict mutations and the SubnetPool allocate/release, AND wrap the allocate+links-membership check in one critical section (fixes the subnet race). For create_node/create_link use reserve-then-build: under the lock allocate the id and insert a PENDING placeholder so a concurrent caller sees it taken, release the lock for the docker work, then promote under the lock. In get_topology snapshot under the lock: nodes=list(self.nodes.values()); links=list(self.links.values()) before building dicts.
- **Prevention:** All state mutation routes through one serialized owner; check-and-insert is atomic regardless of how slow the build is, and reads see consistent snapshots — no torn reads or duplicate allocations.
- **Risk:** Holding the lock across full create_link would serialize long ops; keep it narrow. get_topology runs on the event loop so acquiring a threading lock there briefly blocks the loop — keep that critical section to just the snapshot. Add a concurrency regression test (parallel create_link/delete_node while polling get_topology, assert no RuntimeError).

### #9 — Offload all blocking docker calls off the event loop and serve stats from one background poller
**Severity:** high · **Effort:** medium · depends on [8]  
**Files:** `backend/api/websocket.py`, `backend/main.py`, `backend/api/nodes.py`

- **Problem:** ws_topology/ws_logs (async) call blocking subprocess.run docker exec directly on the event loop (websocket.py 37-52, 68), freezing the whole loop for all clients (N*5s+M*5s per cycle, total stall if docker hangs). Top-level sync routes (main.py 54-80) and get_node (nodes.py 34-41, which also mutates shared state in a GET) run heavy unbounded blocking work on the anyio threadpool, risking pool exhaustion and full stall.
- **Fix:** Wrap every blocking manager call made from a coroutine in asyncio.to_thread (e.g. await asyncio.to_thread(manager.get_bpsink_output, node_id, 100)). Introduce one background polling task that gathers all per-node stats on a cadence under the lock and stores a snapshot; ws_topology/ws_logs and GET /api/bundle-stats serve that snapshot via broadcast(), making docker load O(1)/interval regardless of client count. Make get_node async, offload get_bundle_count, and stop mutating the shared Node in the GET (compute bundles_received into the returned dict or read from the poller snapshot); add a generic-exception handler so a docker TimeoutExpired maps to a mapped error, not an unhandled 500. Add a code-review rule: no synchronous DockerManager/subprocess call from an async def.
- **Prevention:** A single background poller plus to_thread offloading decouples docker latency from the event loop and from client count, structurally preventing per-client loop stalls and threadpool exhaustion.
- **Risk:** to_thread uses the same pool, so the load reduction comes from the single-poller snapshot, not to_thread alone. Ensure the poller acquires the same lock as rank 8. Test with a slow/hung docker exec and assert other clients stay responsive.

### #10 — Schema-validate imported scenarios before any destructive cleanup, and make import transactional
**Severity:** medium · **Effort:** medium · depends on [2]  
**Files:** `backend/api/scenarios.py`, `backend/models.py`

- **Problem:** _do_import (141-213) and the duplicate _do_import_file (241-307) call cleanup_all() BEFORE validating, then feed node_def['id']/node_a/node_b verbatim into create_node/create_link. A missing 'id' raises mid-sort AFTER teardown (destroying the live topology), and create_link 409s are swallowed into errors[] while the endpoint still returns 200 'imported'. version is stamped on export (1.2) but never checked. Unbounded await file.read() is a memory DoS, and an unbounded nodes list spawns unbounded privileged containers.
- **Fix:** Extract one shared import helper used by both endpoints. Define Pydantic models (NodeSpec{id: conint(ge=1, le=MAX)}, LinkSpec{node_a, node_b: int}, Topology) and parse the upload through them, returning 422 on malformed input. Cap upload bytes (read with a limit) and cap node/link counts (MAX_NODES/MAX_LINKS) BEFORE any create. Validate referential integrity (every link endpoint is a declared node, ids unique) and validate version against SUPPORTED_VERSIONS — all BEFORE calling cleanup_all(). Track resources created during this import and, on any create failure, roll back (or run cleanup_all) and return non-2xx so created<requested cannot read as success. Coerce node id to int at the create_node boundary (defends the export->reexport laundering path).
- **Prevention:** Validate-before-destroy guarantees a malformed/oversized file can never wipe a working topology, and a transactional import never leaves orphans or reports partial failure as success.
- **Risk:** Apply to BOTH import paths (they are duplicates) or the bug persists. Version hard-reject may be over-strict for forward-compat (a warning may suffice for unknown minors). Depends on idempotent create_link (rank 2) for clean retries.

### #11 — Thread convergence_layer through ION config generation (silent TCP-only topology)
**Severity:** high · **Effort:** medium  
**Files:** `backend/services/ion_config.py`, `backend/services/docker_manager.py`

- **Problem:** Link.convergence_layer (tcpcl/udpcl/ltpcl/stcpcl) is set on import and round-tripped on export but every generator hardcodes tcp/4556/tcpclo (ion_config.py 65-104; docker_manager.py also re-hardcodes 'a plan {peer} tcp/...' at 543-544 and in create_link 195-202). A udpcl/ltpcl scenario silently runs as TCP; export says udpcl, re-import produces tcp — lossy and misleading.
- **Fix:** Add a single CL_REGISTRY dict (cl -> protocol token, induct/outduct daemon, port) consumed by ion_config (generate_node_rc/add_outduct/add_plan/delete_outduct) AND by the docker_manager runtime add/delete paths (195-202, 231 loop, 543-544, 836-849) and the neighbors-dict builders (508/510). Pass each link's convergence_layer through these calls. Validate the CL against the registry and raise on unknown values so an unsupported CL fails loudly instead of becoming TCP. Note LTP needs ltpadmin spans (not a simple host:port outduct) — for now support tcp/udp/stcp via the token swap and raise on ltp until proper LTP handling is added. Add a round-trip test (export->import->read live plan) and a per-CL generator test.
- **Prevention:** Centralized CL registry consumed everywhere closes the 'model field that never reaches the generator' class; validation makes unsupported CLs fail loudly.
- **Risk:** Must touch all the scattered hardcoded callsites, not just ion_config. LTP semantics differ — gate it behind a raise rather than emit wrong config.

### #12 — Make ION admin parsing/route mutation declarative and verified (exits, plans, propagate_routes)
**Severity:** medium · **Effort:** medium · depends on [2]  
**Files:** `backend/services/docker_manager.py`

- **Problem:** Multiple divergent parsers for ipnadmin 'l exit'/'l plan' output: _clear_node_exits (557-570) splits positionally and reads parts[0]='From' -> int() fails and is swallowed, so it deletes nothing; _list_plan_peers (883-901) regex does not match real 'l plan' output, so repair re-adds plans and emits the 'Duplicate egress plan' warning it claims to avoid. _propagate_routes (727-751) clears then re-adds exits with all exceptions swallowed and no verification, leaving a node with fewer routes on partial failure. _docker_exec swallowing non-zero exits hides all of this.
- **Fix:** Add one shared parse_exit_line()/parse_plan_line() helper (reusing the working list_exits regex) consumed by list_exits, _clear_node_exits (emit d exit {first} {last}), _propagate_routes, get_node_config, apply_raw_exit. Convert _propagate_routes to a declarative reconcile: parse the live exit set, diff against the BFS-desired set, apply only add/delete deltas, collect failures into an errors list (mirror repair_ion_config), then re-list and verify the live set matches desired; surface the errors through set_all_exits/set_node_exits and their endpoints (main.py 67, nodes.py 124). Treat ION 'Duplicate'/'already exists' responses as success so a parse miss cannot cause spurious errors. This relies on _docker_exec surfacing returncode/stderr (rank 2).
- **Prevention:** A single shared parser plus desired-state diff+verify replaces clear-then-rebuild fire-and-forget, so route mutations are idempotent, observable, and never produce a net route loss.
- **Risk:** Plan-line regex must match the real ION version output (capture leading integer of each plan line, not IP octets) — add a fixture test from a live node. Verify step depends on returncode surfacing.

### #13 — Fail loud on ION startup and add readiness signaling (entrypoint, HEALTHCHECK, _wait_for_ion_ready contract)
**Severity:** medium · **Effort:** small · depends on [2]  
**Files:** `docker/entrypoint.sh`, `docker/Dockerfile.ion`, `backend/services/docker_manager.py`

- **Problem:** entrypoint.sh (21-31) ignores ionstart's exit code, prints 'OK: Node ready' and execs tail -f /dev/null regardless, so a failed ION start yields a container Docker reports as running with no BP stack. There is no HEALTHCHECK (Dockerfile.ion 24-25). _wait_for_ion_ready (857-875) falls through silently after timeout with no return value, then create_link configures a dead node and records the link UP.
- **Fix:** Harden entrypoint.sh: check ionstart's exit code and exit 1 on failure (so Docker marks the container failed). Give _wait_for_ion_ready a bool/raise contract (True only when bpadmin responds), and in create_link gate on it: on not-ready, record the link status=ERROR/DEGRADED (and roll back the network per rank 2) rather than UP, and add a post-create verification (list plans, confirm the new peer present). Optionally add a HEALTHCHECK that probes ION via the same bpadmin liveness check used by _wait_for_ion_ready (not bpstats), and have create_node reflect an Exited container as a failed NodeStatus instead of unconditionally RUNNING (line 111).
- **Prevention:** Distinguishes 'process started' from 'service ready' with an explicit readiness contract and fail-loud entrypoint, so partial ION-startup failures become detectable/cleanable states instead of silently polluting the topology.
- **Risk:** Raising in _wait_for_ion_ready must be paired with create_link rollback (rank 2) or it leaks the already-created network/subnet. No restart policy means no crash loop. The .ready marker is dead unless a reader consumes it — prefer the bpadmin probe.

### #14 — Fix bundle-stats counting and parsing (windowed tail treated as cumulative; brittle bpstats regex)
**Severity:** medium · **Effort:** small  
**Files:** `backend/services/docker_manager.py`

- **Problem:** get_bundle_count (364-369) does re.findall over tail -500 of bpsink.log and returns the match count, which silently caps/decreases once the log exceeds 500 lines while being reported as a cumulative metric. get_bundle_stats (393-411) greps tail -20 of ion.log with a format-fragile regex, has no sync between triggering bpstats and reading, and swallows all exceptions so parse failure looks like an idle node.

### #15 — Centralize FastAPI error mapping and the manager dependency (consistent status codes, no opaque 500s)
**Severity:** medium · **Effort:** medium  
**Files:** `backend/api/links.py`, `backend/api/nodes.py`, `backend/api/traffic.py`, `backend/api/scenarios.py`, `backend/main.py`

- **Problem:** Routes catch ValueError then except Exception->500 with raw str(e), so a docker 409 becomes 500, a NotFound becomes 500, a TimeoutExpired becomes 500, and daemon internals leak to clients; several routes have no handler so faults map inconsistently. Every API module uses a module-global manager=None set by main.py (40-44); reaching a route before injection yields an opaque AttributeError 500.
- **Fix:** Define a small domain exception hierarchy (NotFoundError, ConflictError, BackendTimeout) raised by DockerManager and register app.add_exception_handler mappings: docker APIError->its .status_code (409->409), NotFound/NotFoundError->404, subprocess.TimeoutExpired/BackendTimeout->504, ConflictError->409, ValueError->400, catch-all->500 with a generic message while logging the real exception server-side (never return str(e)). Remove per-route catch-alls once global handlers exist. Replace the manager=None globals with FastAPI DI: set app.state.manager in lifespan (currently never set) and add get_manager(request) that raises 503 if None; convert route signatures to manager: DockerManager = Depends(get_manager). (Lighter alternative if the DI refactor is too broad: a shared top-of-route guard raising 503 when manager is None.)
- **Prevention:** One central error-mapping layer gives every route consistent, correct status codes with no internal-detail leakage; DI makes it impossible to reach a route with an uninitialized manager and makes the manager mockable.
- **Risk:** Bare ValueError can't globally pick 400 vs 404 (used for both) — the domain exception hierarchy resolves this. The DI conversion touches all five modules; the guard alternative is lower-churn.

### #16 — Pin and verify build provenance, add HEALTHCHECK, and harden the export library
**Severity:** medium · **Effort:** medium

### #17 — Centralize and harden frontend fetch + WebSocket lifecycle + mutation guard + server-truth reconciliation
**Severity:** medium · **Effort:** medium · depends on [9]  
**Files:** `frontend/js/app.js`

- **Problem:** apiPost/apiDelete call res.json() before checking res.ok (62-78), so non-JSON error bodies (502/504 HTML, crash) throw 'Unexpected token <' and HIDE the real 409. The per-node log WS never reconnects (empty onclose 283-284); the topology WS reconnects on a flat 5s timer with no backoff and leaks handlers/timers. fetchTopology/fetchBundleStats swallow all errors with no UI signal, leaving stale topology displayed. Only addNode guards against double-submit; other mutations can double-fire and create duplicate networks. Optimistic terminal/graph state is destroyed before the POST and not reconciled on failure. importInProgress is an un-timed boolean gating both poll and WS that can stick forever. Stale bundleStats badges persist after node id reuse.
- **Fix:** Centralize all fetch in one apiFetch() that reads text first, parses defensively (JSON.parse in try/catch), and on !res.ok throws Error(data.detail || `${res.status} ${res.statusText}`); migrate the inline fetch sites (791-792, 1359-1366, 1418-1423) onto it (with a non-JSON/blob success path for export-bundle). Add a makeResilientSocket(url,{onMessage}) factory with capped exponential backoff + jitter + single-timer guard + handler cleanup, build both topology and log sockets from it, and make socket-owned reconnect the single recovery owner (remove the syncTerminals readyState-driven recreate to avoid racing); clear timers in destroyTerminal and on node removal. Add a connectionState (connected/degraded/disconnected) driven by both poll and WS, render a header indicator, and gate mutating buttons on it; surface a banner after N consecutive failures. Funnel all mutations through runMutation(fn) owning an in-flight lock (cleared in finally) + loading overlay + catch->toast. Stop destroying terminals optimistically (remove pre-POST destroyTerminal loops in cleanupAll 1215 and handleImportFile 1411) and let syncTerminals reconcile from fetched topology; on mutation failure force an immediate fetchTopology. Set importInProgress inside the try (or immediately before with try as next statement) and show a visible Importing state. Add a backend topology/stats epoch id; client flushes bundleStats and renders only newer epochs.
- **Prevention:** One fetch wrapper, one socket factory, one mutation chokepoint, and server-epoch-driven reconciliation make error-surfacing, reconnection, double-submit prevention, and stale-cache invalidation impossible to forget per-callsite.
- **Risk:** Removing optimistic destroy + relying on the poll widens the reconcile window slightly (mitigated by forcing fetchTopology in catch). The epoch id requires a small backend change. Low blast radius (single-user lab UI).

## Architectural recommendations

- Make the Docker daemon the single source of truth: a mandatory reconcile()/adopt() at manager startup that rebuilds nodes, links, ip assignments, node-id counter and subnet pool from labeled live resources (containers + network.attrs IPAM/Containers). In-memory dicts are a cache of Docker, never an independent truth.
- Add explicit ionmgr.node_id / ionmgr.link_id labels on every created resource so reconcile parsing is robust to name-format drift, and make SubnetPool support reserve(idx)/from_live() so allocation is derived from in-use subnets with an explicit /16 upper bound.
- Adopt a uniform create-then-rollback + idempotent get-or-create pattern for every multi-step provisioning path (networks, containers, ION config), with state recorded as PENDING before side effects and promoted to UP/ERROR based on verified outcome — never recorded UP on the success-only path.
- Separate process lifecycle from resource lifecycle: startup reconciles/adopts, graceful shutdown preserves by default, destruction is an explicit operator action gated by a flag; reconcile stop.sh and the lifespan handler so they agree. Optionally persist intended topology to detect/repair drift.
- Establish a single-writer concurrency model: one threading.RLock guarding all state mutation (narrow critical sections, slow docker work outside the lock) plus one background poller that owns per-node stats and broadcasts snapshots, so docker load is O(1)/interval and no async coroutine ever calls blocking subprocess directly.
- Funnel all untrusted I/O through hardened chokepoints: one argv-based container-exec primitive (no bash -c interpolation), one _safe_scenario_path filesystem helper, one Pydantic ScenarioModel import contract, one FastAPI error-mapping layer + DI for the manager, and matching single-helper patterns on the frontend (apiFetch, makeResilientSocket, runMutation).
- Default the control plane to localhost + mandatory auth token (covering WebSockets), drop privileged=True to cap_drop=ALL + cap_add=[NET_ADMIN, IPC_LOCK], and pin/verify all build inputs (ION commit, base image digest, apt versions, hashed Python deps) since the runtime is privileged.

## Prevention checklist (invariants to keep the incident class impossible)

- [ ] On every manager startup, reconcile() runs and adopts/reseeds from labeled Docker resources; an invariant test constructs the manager twice over the same live topology and asserts nodes/links/subnets match the daemon.
- [ ] No Docker resource is ever created with an unconditional networks.create()/containers.run() — all creation goes through idempotent get-or-create helpers keyed by deterministic name, and a test injects a pre-existing same-named network and asserts no 409.
- [ ] Every multi-step provisioning method is wrapped in try/except with compensating rollback; a test injects a mid-create failure and asserts no orphan network/subnet/container/config-dir remains and no link is recorded UP.
- [ ] Subnet and node-id allocation are seeded from live Docker state with an explicit upper bound; allocation never depends solely on an in-memory counter and raises a clear error on exhaustion instead of emitting invalid octets.
- [ ] start.sh runs the shared label-based orphan prune before launch (only when no live owned instance exists); cleanup loops isolate failures per item and guarantee all phases run (a test injects a remove() failure and asserts other orphans are still reaped).
- [ ] No DockerManager state is mutated without holding the manager RLock, and no synchronous DockerManager/subprocess call is invoked from an async def — both enforced by a code-review/lint rule; a concurrency test runs parallel create/delete while polling get_topology and asserts no RuntimeError.
- [ ] No container command is built with bash -c plus interpolation (CI grep enforces argv-only exec); send_bundle is tested with quotes/$()/backticks and asserts no shell execution.
- [ ] Every scenario filesystem access goes through _safe_scenario_path; a test asserts '../' and absolute names cannot escape SCENARIOS_DIR for export, import, and delete.
- [ ] Imported scenarios are schema-validated (Pydantic, bounded ids, capped node/link counts, bounded upload bytes, referential integrity, version) BEFORE any cleanup_all(); a test feeds a malformed/oversized file and asserts the live topology is untouched and the response is non-2xx.
- [ ] The control plane binds 127.0.0.1 by default, refuses anonymous 0.0.0.0 exposure, requires an auth token on all routes including WebSockets, and runs containers with cap_drop=ALL (no Privileged=true) — asserted by a test that no managed container has Privileged=true.
- [ ] ION config generation honors convergence_layer via a single CL_REGISTRY (round-trip export->import test) and fails loud on unsupported CLs; ION admin output is parsed by one shared helper with fixture tests, and route mutations are declarative diff+verify.
- [ ] Container readiness is gated on an explicit bpadmin probe / HEALTHCHECK (not a fixed sleep), entrypoint.sh exits non-zero on ionstart failure, and a node whose ION failed is reflected as a failed NodeStatus, not RUNNING.
- [ ] All build inputs are pinned and verified (ION commit/tag, base image digest, apt versions, hashed Python deps) and CI fails if anything is unpinned.
- [ ] Frontend routes all fetches through apiFetch (defensive parse + status), all sockets through makeResilientSocket (backoff+jitter+single-timer), all mutations through runMutation (in-flight lock), and reconciles UI from server truth via a topology/stats epoch so stale or fabricated state cannot persist.
